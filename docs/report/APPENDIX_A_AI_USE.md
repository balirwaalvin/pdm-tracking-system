## How it was used

- **Code.** The student wrote the plan, the scope rules and the order of work (the `CLAUDE.md` brief in the repository), and reviewed each step. The AI wrote code, tests and commits under that brief. Each AI-assisted commit is marked `Co-Authored-By: Claude` in the Git history, so the extent of AI help can be checked.
- **Decisions made by the student,** not the AI: the choice of PDM; the e-government-only scope; the ten roles; the use of a USSD simulator instead of the Africa's Talking sandbox; the addition of maker-checker, Luganda USSD, appeals and success stories; and the visual direction.

## How we checked the AI's work

- 291 automated tests run on every change, and the build must pass before deployment.
- Manual walkthroughs of all ten roles, plus rehearsals of the demo on the live site (23 and 25 Nov 2026).
- An accessibility scan (axe-core) and a security sweep (logged-out and cross-parish access).
- Every group member must be able to explain the part they own in the oral defence.

## Data and privacy
